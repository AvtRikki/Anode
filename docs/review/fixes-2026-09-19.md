`HierarchySafetyTests` exercises the core without downloaded fixtures. `DocumentSafetyTests` exercises the workbench with controlled asynchronous documents and the real schematic plugin. Existing fixture tests now pass the test cancellation token to the extended hierarchy API.

## Behaviour and limits

- File creation refuses to replace an existing final output even after a file picker overwrite confirmation. Choose a different name or move the existing project first.
- Save As to another open tab's path is refused. Save or close that tab before choosing its path. Saving a document to its own path remains supported.
- Path reservations belong to the workbench and use normalized absolute paths (case-insensitive on Windows). They do not implement cross-process file locking or resolve every symbolic-link/hard-link alias.
- Publishing two project files is not a filesystem transaction. A handled failure rolls back the newly published project file; a process crash between the two moves can leave that file behind. Existing files are never intentionally replaced by creation.
- Hierarchy diagnostics shown in Checks describe the initial load. Reopen the document to refresh them after repairing a file externally. Partial hierarchies may yield incomplete design-wide results; their diagnostics must be resolved before relying on those results.
- Traversal retains a maximum depth of 32 and adds a total limit of 10,000 sheet instances. Reaching either limit produces a diagnostic.
